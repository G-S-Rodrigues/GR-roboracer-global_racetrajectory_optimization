# Testing the fork

IDs are `TUMFORK-<tier><nnn>` (as GR-roboracer's `<PKG>-<T>NNN`). Run in `gr-tum-dev`.

| Tier | What | Where | Run |
|---|---|---|---|
| 1 | pytest, no solver | `tests/unit/` | `pytest tests/unit` (`-k tumfork_1040` for one) |
| 4 | Robot Framework, full TUM solves in a subprocess | `tests/acceptance/` | `robot --pythonpath tests/lib:tests/fixtures --outputdir log/robot --include fast tests/acceptance` |

Robot tags: `fast` runs in `--ready` and CI; `heavy` (the Spielberg gym solves) runs in `--full` and
by `workflow_dispatch` with `full`. Robot lives only at tier 4 (GR-roboracer ADR 0004); the keyword
lib `tests/lib/tumfork_keywords/` is a thin adapter over `runner.py`.

Gates: `scripts/check.sh --fast` (ruff on the fork's own files + tier 1), `--ready` (+ Robot `fast`),
`--full` (+ `heavy`).

Data comes from the submodule `third_party/GR-roboracer-data` (`git submodule update --init`); the
oval fixture is generated by `tests/fixtures/make_oval.py`. Bitwise comparisons (4010) hold only
inside one container run with `OPENBLAS_NUM_THREADS=1`; never compare across machines.
